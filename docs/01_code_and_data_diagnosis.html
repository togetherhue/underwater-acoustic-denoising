轻量化水声信号降噪模型 — 代码与数据诊断报告

对象：D:\project\降噪模型\Complete_Denoised_Model.py · 数据：D:\project\tr_signal(1)\tr_signal\chirp_with_noise_1.mat 及同项目全部数据/权重/输出
方法：静态代码审查 + 全部 .mat 二进制解析 + 对 output/ 已保存结果的独立复算
一句话结论：这份代码在当前数据上一行都跑不通；即使把路径和变量名修好让它跑通， 由于所有训练样本共用同一个干净目标，它优化的其实是"从信道畸变+强噪声里重建某一个已知波形"， 而不是"降噪"。已保存结果中那个 +16.7 dB 的增益，无法证明模型具备实际降噪能力。

二、阻断性缺陷：代码在当前数据上无法运行

1. 数据路径全部写死在另一个盘

CFG 里 train_dir / test_dir / finetune_dir / target_signal 全指向 E:/LNN_denoised/LNN_Denoise/NN_Code/，而数据实际在 D:/project/。第一次 os.listdir 就会抛 FileNotFoundError。

2. 读取的变量名在三个数据集里对不上

DenoiseDataset.__getitem__ 固定读 ['chirp_with_noise']，但：

  • tr_signal（两批全部 6784 个文件）→ 变量名是 noisy_signal → KeyError
  • te_signal（11 个测试样本）→ 变量名是 noisy_signal → KeyError
  • 只有 finetune_signal 用 chirp_with_noise，能读

也就是说：训练集和测试集都会直接崩，只有微调集能读。

3. 信号长度被硬编码，与实际数据全部不符

input_size=18549 同时写死在 LayerNorm(18549)、训练和推理三处，形成"长度锁死"：

  • 测试集是 17599 点 → LayerNorm 直接报 expected input with shape [*, 18549]
  • 干净目标 chirp_signal.mat 只有 9600 点，而 __getitem__ 里 min_len 截断会把输入也截成 9600 → 同样报错，且白白丢掉信号后半段 60%
  • April 批训练数据是 9600 点 → 报错

而且：模型文件里 LayerNorm 的尺寸确实是 18549，说明权重是在与当前磁盘上完全不同的数据上训练的。 output/ 里保存的含噪信号长度是 18549、干净目标是 18549——当前 te_signal（17599）和 chirp_signal.mat（9600）都不是当初那次运行的数据。项目状态已经自相矛盾，现有结果不可复现。

4. 文件名排序正则对一半文件失效

sort_files_numerically 用 r"_(\d+)\.mat$" 提取序号。chirp_with_noise_1.mat 能匹配， 但 May 批的文件名是 chrip_with_noise6767.mat（既拼错了 chrip，数字前也没有下划线）→ 全部返回 float('inf')， 排序退化为 os.listdir 的任意顺序。若训练目录指向 May 批，样本序号完全失效。

三、方法论缺陷（这才是真正要命的部分）

5. 所有样本共用同一个干净目标 → 任务退化

DenoiseDataset 里 self.clean_signal 是一个固定的 chirp，对所有 6652 个样本反复使用。 网络要学的因此不是"去噪"，而是"从任意畸变输入里复原这唯一一个已知波形"。这个先验太强，模型完全可以绕开输入直接"背"出目标波形。

6. 训练集里有大量"纯噪声样本"，在教模型凭空生成 chirp

抽样 60 个 May 批样本，rms 从 5.36e-13 到 1.04e-6，跨越 6 个数量级。 中位数 1.7e-7。那些 rms 只有 1e-13 的样本，信号分量已被信道衰减到噪声之下，本质上是纯噪声被贴上了"干净 chirp"的标签—— 这正是训练"幻觉式生成器"的标准配方。

7. 幅度域不一致：输入 1e-7，目标 0.707

网络第一层对输入做 LayerNorm（零均值、单位方差），输出经 tanh 限制在 (−1, 1)； 但损失函数直接拿输出和物理量纲的 clean（幅值 ±1，rms 0.707）比。 归一化域与物理域被混在一起，损失的含义是含混的。

8. snr_threshold = 60 dB 不现实，且与已有结果自相矛盾

实测真实输入 SNR 只有 −1 dB 左右。60 dB 门限意味着"直接输出"分支永远不可能命中， 每个文件都会被强制微调 5 轮。但 output/iterative_transfer_learning_results.txt 里 11 个样本全部记录为 "否 / 0 次微调"，最终 SNR 仅 18 dB——说明那份结果是另一版代码跑出来的，和当前 CFG 不自洽。

9. SNR 指标是自造的，而且会静默失效

calculate_snr_intervals 用"另一个时段的噪声"去减信号段来估"纯信号功率"。问题：

  • 对非平稳噪声、信道畸变信号完全失效。实测：代码对 test_sample_1 自报原始 SNR 5.79 dB，而按 clean 真值算是 −1.44 dB，偏差约 7 dB。
  • 当噪声段比信号段长时 np.tile(x, 0) 返回空数组，signal_part - 空数组 会广播报错——潜伏崩溃。
  • 区间 (1.0, 1.2, 1.6, 1.8) 对 9600 点的信号取 signal[15360:17280] 得到空数组，被 continue 静默跳过——实际只用了 1 段区间，却以为用了 2 段。
  • 区间 (0.8, 1.0, 0.1, 0.3) 和 fs=9600 是对某一批数据写死的，换数据即失效。

四、网络结构缺陷

位置问题
input_norm = LayerNorm(18549) 单个 LayerNorm 就占 37,098 参数，是全模型 99,005 参数的 37.5%。 一个"轻量化"模型里近四成参数花在一个全长度归一化上，且它把模型锁死在固定输入长度。
final_fusion 的 tanh 把输出硬限幅在 (−1, 1)。目标幅值是 ±1，看似刚好，但只要信号幅值超过 1（或需要任何 >1 的动态范围），模型永远拟合不了。 同时这个 tanh 把前面精心设计的"残差连接保持信号主体结构"整个抹掉——residual 加进去再被 tanh 压平，等于没加。
_init_weights 在 __init__ 末尾对所有 Conv1d 做 kaiming 初始化，会把上一行刚设好的 signal_preservation.weight = 1.0 / bias = 0.0（恒等初始化）覆盖掉。那段"保持信号"的初始化是死代码。
频域分支 噪声估计 mask（Sigmoid）和幅度 mask（Sigmoid）级联相乘两次，双重压制导致过抑制； 相位修正系数 0.1 是硬编码常数，无依据。
时/频融合 softmax([time_weight, freq_weight]) 对两个标量做归一化——形式上像注意力，本质只是 2 参数凸组合， 且时域分支输出有 tanh 限幅、频域分支输出无界，两者统计量不一致却直接加权相加。
DepthwiseSeparableConv2d(1, 16, …) 输入通道为 1 时，groups=1 的 depthwise 就是普通卷积，并没有省任何参数。
signal_preservation 1×1 卷积，等价于一个可学习标量，再乘 0.1，纯冗余。
残差 output = residual + 0.3*fused + 0.1*preserved 之后又 + 0.2*x_norm——输入被加了两次。

五、工程与流程问题

  • __getitem__ 每次 sio.loadmat 全量读盘。6652 个文件 × 100 epoch，无缓存、无预处理、无标准化，I/O 会成为瓶颈。
  • torch.save(model.cpu().state_dict()) 紧接 model.to(device)：每次刷新最佳模型都要把整个模型在 CPU/GPU 之间搬两趟。
  • 微调函数每轮都重建 Dataset 和 DataLoader，而微调集只有 13 个样本、batch=2——每轮只跑 7 个 batch。
  • 训练循环用 except Exception: continue 吞掉一切异常。avg_loss 可能只由极少数成功的 batch 算出，却当作整轮指标。
  • 没有设置随机种子，结果不可复现。
  • 项目里存在 信道产生 ~ 信道产生6 六份几乎相同的仿真代码副本，以及 data/data1/data2/data(1) 多份数据副本，版本管理混乱。
  • 训练集重复：April 批 132 个文件只有 19 个唯一（85% 是重复样本），会严重加剧过拟合。

六、我做的独立复算（对 output/ 里 27 个已保存结果）

指标数值含义
corr(noisy, clean) 平均0.022含噪输入与干净目标几乎不相关，真实 SNR ≈ −1 dB
corr(denoised, clean) 平均0.985输出与干净目标高度相关
真实 SNR 增益（以 clean 为参考）平均 16.67 dB−1 dB → 约 +13 dB，最高 +22 dB
代码自报平均增益13.35 dB自报"原始 SNR" 5.79 dB vs 真实 −1.44 dB，指标偏差约 7 dB
27 个输出两两之间的相关0.977输出彼此几乎一样，而输入彼此几乎不相关。由于所有样本的目标本就是同一个 chirp， 这一现象无法区分"完美降噪"与"直接生成固定波形"——现有实验设计缺少判别能力。
27 个输入两两之间的相关0.026
这意味着：要证明模型真的在降噪，必须补一个"目标信号不在训练集中"的测试集。 当前设计下，无论模型是真的会降噪还是只会背波形，都会得到同样漂亮的数字。

七、修改建议（按优先级）

P0先让实验具备说服力

  1. 目标信号必须多样化。用不同中心频率 / 调频斜率 / 时延 / 幅度 / 初相的 chirp（或实测 HFM）做目标， 并把训练目标与测试目标严格分离。这是整个工作的前提。
  2. 明确任务边界。如果目标是"信道均衡"，就把它当反卷积做，并给出信道估计；如果只是"降噪"， 就应当把 conv(chirp, H) 作为"干净信号"、只叠噪声作为"含噪信号"，不要混在一起。
  3. 换掉 SNR 评估。直接用 10·log10(‖s‖²/‖ŝ−s‖²)，参考真值 s。 同时补 SI-SDR / PESQ / STOI 等客观指标，并按帧分段统计。
  4. 修数据读取：变量名改为自动探测（noisy_signal / chirp_with_noise 兼容）， 或统一生成端命名。
  5. 去掉硬编码长度：要么全局统一长度，要么用自适应池化 / 可变长 STFT 让模型支持任意长度。 把 LayerNorm(18549) 换成逐帧归一化（如 LayerNorm 作用在频点维）或直接删掉——它是 37.5% 的参数负担。

P1修数据质量

  1. 删除 132 个重复样本中的 113 个重复项；检查 May 批是否也有隐藏重复。
  2. 剔除 rms 低于噪声底线的样本（信号被完全淹没的样本只会教模型幻觉）。
  3. 生成时记录每个样本的真实 SNR，按 SNR 分层采样，避免 6 个数量级的幅度跨度。
  4. 把数据预加载成单个 .npz 或 memmap，替代逐个 loadmat。

P2修模型与训练

  1. 去掉 final_fusion 的 tanh（或改成 输出 = a·input + (1−a)·net(input) 的可学习凸组合）， 否则输出动态范围被永久限制。
  2. 把"残差 + tanh"的顺序理顺：要么 tanh(net) 后与输入相加，要么干脆不做 tanh。
  3. 修复 _init_weights 覆盖恒等初始化的问题（把 _init_weights 移到 __init__ 最前面，或对 signal_preservation 单独重设）。
  4. 把两级 Sigmoid mask 合并为一级（如复值掩码 CRM 或比值掩码 IRM）。
  5. 损失函数去掉与主损失同向的冗余项 noise_reduction 比值项；smoothness_loss 建议改成对残差的 L1， 直接约束"输出 − 输入"的稀疏性，更贴合降噪目标。
  6. 取消 except: continue 静默吞异常，让错误暴露出来；固定随机种子。
报告基于对 D:\project 下全部 .mat 文件的二进制解析、模型权重（99,005 参数）的结构解析， 以及对 output/ 中 27 个结果文件的独立数值复算得出。所有数值均可在项目数据上复现。
