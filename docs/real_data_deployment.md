# 实测数据接入说明（部署前必读）

> 面向：拿到导师提供的实测水声信号后，要把 PAM-Net 直接应用上去的人。
> 结论先说：**当前这版模型不能"直接"用于实测数据，必须先做输入尺度对齐；
> 而尺度无法从数据本身可靠估计 —— 所以正确的做法是在模型内加入输入归一化并重训。**
> 下面是把这条结论量化出来的三组实验。

---

## 1. 模型对输入尺度的要求

训练数据在 MATLAB 侧做了 `clean_signal = clean_signal / rms(clean_signal)`，
即**干净信号的 rms 被归一化为 1**。`PAMDataset` 不再做任何归一化，
所以模型见到的一直是"信号分量 rms ≈ 1"的输入。

实测数据**没有干净参考**，无法做同样的归一化。最自然的替代是 `noisy / rms(noisy)`，
但这相当于把输入整体缩小 `rms(clean)/rms(noisy)` 倍（base 条件下约 1/2.64）。

## 2. 尺度敏感度：这不是小事，是 16 dB

`code/analysis/scale_robustness.py`：取 base testA 120 样本，把输入乘一组缩放因子。

| 缩放 s | 干扰帧增益 (dB) | 相对 s=1 |
|---|---|---|
| 0.10 | 1.90 | **−23.7** |
| 0.38 | 9.69 | **−15.9** ← 按 noisy rms 归一化就落在这里 |
| 0.50 | 12.87 | −12.7 |
| 0.70 | 17.80 | −7.8 |
| **1.00** | **25.58** | **0（训练尺度）** |
| 1.40 | 22.95 | −2.6 |
| 2.00 | 20.81 | −4.8 |
| 3.00 | 19.71 | −5.9 |
| 10.0 | 18.32 | −7.3 |

**关键**：缩放不改变 SNR（信号与噪声同比缩放），所以这**纯粹是尺度敏感**，
不是"任务变难"。最优点尖锐地落在 s=1。

## 3. 盲自校准不可行

`code/analysis/scale_autocalib.py`：测试四个**无参考**准则能否定位最优尺度。

| 准则 | 峰值位置 | 与真实最优 (s=1) |
|---|---|---|
| 带内能量占比 | 0.50 | ✗ |
| 峰度下降 | 0.70 | ✗ |
| 带外抑制 | 1.00 | 巧合 |
| 残差白性 | 2.00 | ✗ |

"带外抑制峰值在 1.00"是数值巧合：它的取值在 0.3338~0.3348 之间波动，
**动态范围仅 0.03%**；其余准则也只有 0.07%~0.7%。全部不足以定位最优尺度。

## 4. 物理估计器也不可行

`code/analysis/scale_estimator.py` / `scale_alignment.py`：信号是窄带 chirp
（798–1500 Hz），噪声宽带，直觉上可以用带外能量估噪声、再反推信号功率。**实测失败**：

| 方案 | s 中位（真值 1.0） | 干扰帧增益损失 |
|---|---|---|
| 带外能量按带宽外推 | 20.0（截断） | **−9.2 dB** |
| 噪声段参考（A） | 1.107 | **−5.6 dB** |
| 同上（B，含突发） | 0.616 | **−9.8 dB** |

失败原因各不相同，但都是根本性的：

- **带外外推失效**：α 稳定噪声是**脉冲性**的，带外功率被少数尖峰主导，
  与带宽不成比例（估计的 rms 偏小约 300 倍）。
- **噪声段参考失效**：`Pc = P_total − Pn` 里 `P_total` 还含**突发干扰**能量，
  导致 Pc 被高估、s 被低估（0.616 vs 1.0）。
- **假定训练 SNR 失效**：实测数据的 SNR 未知，s 的四分位距达 0.68，远超容差。

## 5. 结论与建议

**不要**把实测数据按 `noisy / rms(noisy)` 归一化后直接喂进模型 —— 会损失约 16 dB，
比"用理想带通"还差。

**推荐方案（按优先级）**：

1. **【根本解法】在模型内加入输入归一化并重训。**
   在网络最前面加一层 `x / (rms(x) + eps)`（或可学习的尺度参数），输出端再乘回去。
   这样模型对输入尺度不变，实测数据无需任何标定。改动约 5 行，需重训全部配置
   （GPU 下每轮 65 s，15 轮约 16 min，6 个配置约 1.6 h，完全可承受）。

2. **【过渡方案】若必须用现成 checkpoint**：需要实测数据提供
   ① 明确的**纯噪声段**（无信号、无突发）用于估 `Pn`，
   ② 一个**不含突发**的信号段用于估 `Pc`（例如挑无突发的连续片段）。
   两者都满足时，`s = 1/sqrt(Pc)` 才是可靠的。**注意**：含突发的片段不能用。

3. **【最省事的近似】** 若实测数据的 SNR 分布与训练集接近（有效功率 SNR 约 −7.8 dB，
   即 `rms(noisy)/rms(clean) ≈ 2.64`），可令 `s = 2.64 / rms(noisy)`。
   但这是**有偏**的，误差随 SNR 偏离而增大（实测损失 5.6 dB），只能作粗对齐。

## 6. 拿到实测数据后的检查清单

- [ ] 采样率是否为 24 kHz（模型链路假设 9600→24000→降采样 4 倍→6000 Hz）。
      若不是，需要先重采样到 24 kHz，否则频带与训练不符。
- [ ] 信号是否落在 798–1500 Hz（降采样后）。可用 `code/analysis/band_check.py` 核对。
- [ ] 单段长度是否 ≥ 8000 点（降采样后，即 1.33 s）。不足会被零填充。
- [ ] 是否存在突发干扰。若没有，脉冲感知分支无用武之地，
      应直接用 R3（纯频域掩码，5,910 参数）或 R4（无脉冲分支，14,367 参数）。
- [ ] 输入尺度：按上面第 5 节处理。
- [ ] 无干净参考时的评价：不能用 SNR/SI-SDR。可用的替代指标：
      带内/带外能量比、谱平坦度、以及人工听感抽检。

## 7. 复现

```bash
python code/analysis/scale_robustness.py     # 尺度敏感度曲线
python code/analysis/scale_autocalib.py      # 盲准则能否定位最优尺度
python code/analysis/scale_estimator.py      # 物理估计器（带外外推）
python code/analysis/scale_alignment.py      # 三种对齐方案的定量比较
```

结果分别落在 `results/sensitivity/scale_*.json`。
